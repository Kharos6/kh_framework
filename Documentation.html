Reference for the KH Framework for Arma 3: the scripting commands added by its extension (Part A), its SQF functions (Part B), the globals, events and script locals it exposes (Part C) and the config classes an addon or mission can define (Part D). Written in the style of the Bohemia Interactive community wiki.

Conventions used on this page

  • Types use the engine's names: SCALAR, STRING, BOOL, ARRAY, CODE, OBJECT, GROUP, SIDE, LOCATION, NAMESPACE, DISPLAY, TEAM_MEMBER, HASHMAP, ANY, NOTHING.
  • [a, b, (c)] – elements in parentheses are optional. A missing element, or nil, takes the stated default.
  • Argument faults are logged to the RPT (and raised as a script error) and the command returns its failure value (nil, false, "" or [] as stated).
  • "Client only" means the command is a no-op that returns its failure value on a dedicated server or headless client.
  • Keyword strings are case-sensitive unless stated otherwise.

Part A – Commands

1. Shared argument specifications

1.1 Target (CBA dispatch)

Used by execute, triggerCbaEvent, luaTriggerEvent, luaEmitVariable, luaSetVariable, writeKhData. Decides on which machine(s) something runs. Keywords are case-sensitive.

Value Type Runs on
true (default) BOOL This machine only
false BOOL Nowhere (JIP is still registered if given)
n SCALAR Machine with owner id n (2 = server, own id = local). Negative: every machine except abs n
object OBJECT Where the object is local
team member TEAM_MEMBER Where its agent is local
group GROUP Every machine owning a unit of the group
side SIDE Every player of that side
location LOCATION Every player inside the location
"LOCAL" STRING This machine
"SERVER" STRING The server
"GLOBAL" STRING Every machine, including this one
"REMOTE" STRING Every machine except this one
"PLAYERS" STRING Every player machine
"HEADLESS" STRING Every headless client
"ADMIN" STRING The admin machine
"CURATORS" STRING Every player with an assigned curator
"<uid>", "<playerId>", "<headlessId>" STRING That machine (string starting with a digit 1–9, no :)
"<netId>" STRING Owner of that object, or every owner of that group (string containing :)
any other STRING STRING Players whose name / roleDescription matches; else groups with that groupId; else players inside the marker of that name
[t1, t2, …] ARRAY Union of the above (nested arrays are flattened); resolved on the server
{ … } CODE Predicate evaluated on every machine with the arguments as _this; runs wherever it returns true

1.2 JIP (CBA dispatch)

Used alongside a target by the same commands. Makes the dispatch replay for players who join later.

Value Meaning
false (default) No JIP
true JIP with dependency true, no unit required, generated id
[dependency, (unitRequired), (jipId)] dependency (default true) – checked each time a player joins; the replay is skipped while it fails. unitRequired: BOOL (default false) – deliver only once the joiner's unit exists. jipId: STRING (default "" = generated) – reusing an id replaces the entry

Dependency forms: BOOL (false = never replay) · SCALAR owner id that must still be connected · OBJECT / GROUP / TEAM_MEMBER that must not be null · STRING: a netId / player uid / player id that must still exist, or any other string naming a missionNamespace variable that must be true · CODE that must return true · ARRAY of the above (all must hold).

Commands that return a JIP handle return [missionNamespace, jipId, 2], removable with removeHandler.

1.3 Target & JIP (KH Network)

Used by khNetworkMessageSend and khSetVariable. Same forms as 1.1 with these differences:

  • Keywords are case-insensitive.
  • A CODE target is evaluated on every machine with no arguments; delivered where it returns true.
  • nil target sends nothing (returns false).
  • JIP additionally accepts a plain STRING key, and an ARRAY dependency must be an OBJECT or GROUP. The JIP store lives on the server; entries are replayed to every joiner regardless of the original target. Remove with khNetworkMessageRemoveJip.

1.4 Functions as STRING

Wherever a command accepts a function as CODE | STRING, a STRING may be:

String Treated as
Name of an engine/KH command (case-insensitive) That command, called with the arguments as [], [right] or [left, right]
Bare global function name (no space, no .sqf), e.g. "KH_fnc_foo" missionNamespace getVariable – fetched from the server if not defined locally
Path containing .sqf compileScript
Anything containing a space compile

1.5 Effects chain

Used by ttsSpeak, ttsUpdateSpeaker, tsApplyVoiceEffects: an ARRAY of [name, value] pairs (STRING, SCALAR), applied in order. The whole chain may also be passed as a single nested element. Unknown names are skipped; values are clamped.

1.6 Rendering value shapes

Used by every command in sections 14–17. All keyword strings are case-insensitive. Every BOOL slot also accepts a SCALAR (0 = false, non-zero = true), except where a number would be read as a yaw (the rotation slots and the chain key endRotation), allowDynamicShadows (a real BOOL only), the material key vertexStatic (a number) and a generated mesh's shading (a number is a crease angle).

Shape Layout
position [x, y, zASL] – exactly 3 SCALARs
rotation nil (identity), SCALAR yaw, [pitch, yaw, roll] (degrees), [vectorDir, vectorUp], or OBJECT (turn with it every frame)
color [r, g, b, a] – 0–4 SCALARs; rgb 0–65504, a 0–1
band [minDist, maxDist, (falloff)] metres from camera; maxDist <= 0 = unbounded; falloff default 10; [] = none
blend "normal", "additive", "multiply", "screen", "lighten", "darken" or SCALAR 0–5
duration SCALAR seconds, or [fadeIn, hold, fadeOut]; 0 / [] = permanent. Real time
effect builtin name or id (see 15.1), "*.hlsl" user shader, "*.cube" LUT
params ARRAY of up to 12 SCALAR or nil (keep default), in the effect's lane order (see 15.1)
textures [[path, slot, ("srgb"|"linear")], …] – slot "user0"…"user5", each once; colour space default "linear"; image png/jpg/jpeg/tga/bmp/dds/paa/pac; [] = none

Files (.fbx, .hlsl, .cube, images) are searched in Documents\Arma 3\kh_framework\rendering\, then every mod's rendering\ folder – as a path relative to that folder, then by file name alone at its top; a path with a single leading \ is read from the loaded PBOs.

Rules shared by sections 14–17

  • A malformed argument is reported as an error and the command returns its failure value ("" from a creator, false otherwise). Creators take exactly the elements shown – an extra element is an error, not ignored. In a batch update each failed triple is reported with its index.
  • A number outside a key's range is clamped to it silently; NaN is refused. Refused with a report instead: the integer choices given as numbers (blend, mode, an effect, shape or mesh id), a material's fresnel and vertexBound, the texture-animation keys, simulationLod pairs out of order, and an affector's lifetime, position, vectorDir or scale that is not finite (or a scale half-extent of 0 or less). Also: an object to follow that is null or unreadable fails the call without a report.
  • Graphics run only where there is an interface: on a dedicated server or headless client every rendering command returns its empty value ("" / false / []) at once and does nothing.
  • Every mission start removes the last mission's meshes, passes and physics affectors and resets setRenderAmbientOcclusion, setSsgiScale and allowDynamicShadows to their defaults. This runs in the framework's pre-init, so a command issued from a preInit function that runs earlier is cleared with the rest: issue the first commands from postInit or later.
  • Durations, lifetimes, texture animation and the cloth / chain simulation run on real time: they continue through the pause menu and ignore setAccTime (time them with uiSleep).

2. Execution & events

execute

Runs a function with arguments on chosen machines: immediately, after a delay, repeatedly, or when a condition is met, with optional timeout, JIP, callback, persistence or player-presence behaviour. Returns a handler for removeHandler.

Syntax 1: arguments execute function - arguments: ANY – _this of the function - function: CODE | STRING (see 1.4) - Immediate, unscheduled, local call.

Return: ANY – the function's return value

Syntax 2: execute function – as syntax 1 with nil arguments.

Syntax 3: arguments execute [function, (target), (environment), (special)] Syntax 4: execute [arguments, function, (target), (environment), (special)]

  • arguments: ANY – _this of the function (default nil)
  • function: CODE | STRING (default {nil})
  • target: see 1.1 (default true)
  • environment: how and when to run (default true). A non-ARRAY value x means [x]. The last element of every layout is an id STRING (default "" = random); reusing an id replaces the running execution that holds it.
  • true / false – immediate; the BOOL is unscheduled (true = call, false = spawn). No handler.
  • ["<delay>", (unscheduled), (id)] – one-shot after the parsed delay (STRING number; > 0 seconds, < 0 frames). "0" runs immediately but still returns a handler.
  • [interval, (immediate), (timeoutRules), (timeoutFunction), (verboseDelta), (unscheduled), (id)] – repeating.
    • interval: SCALAR – > 0 seconds, 0 every frame, < 0 every |n| frames
    • immediate: BOOL (default true) – also run once right now
    • timeoutRules: false none (default) · true one iteration · SCALAR seconds / negative frames · STRING absolute CBA_missionTime · [timeout, (priority), (timeoutOnDeletion)] where timeout is any of the former or [count] iterations; priority BOOL checks the timeout before the run; timeoutOnDeletion BOOL also runs the timeout function on removeHandler
    • timeoutFunction: CODE (default {nil}) – called with the arguments when the timeout ends the execution
    • verboseDelta: BOOL (default false) – _totalDelta is real elapsed seconds instead of diag_deltaTime
    • unscheduled: BOOL (default true)
  • [condition, (immediate), (interval), (timeoutRules), (timeoutFunction), (verboseDelta), (unscheduled), (id)] – conditional.
    • condition: CODE – arguments call condition must return true for the function to run
    • interval: SCALAR (default 0 = every frame) – how often the condition is checked
    • timeoutRules: default true = run once when the condition first holds (a waitUntil); false = run every time it holds, forever; otherwise as above, with the ARRAY form [timeout, (priority), (timeoutOnConditionFailure), (timeoutOnDeletion)] and timeout also accepting [count, (countConditionFailure), (iterationTimeout)]
  • special: extra behaviour (default false)
  • true – same as ["JIP", true, false, ""]
  • ["JIP", (dependency), (unitRequired), (jipId)] – see 1.2
  • ["CALLBACK", (callbackArguments), (callbackFunction)] – callbackFunction (CODE | STRING) runs on the target with callbackArguments as _this; its return value is sent back to the caller, where function then runs with _this = arguments and _argsCallback = that return value. One-shot.
  • ["PERSISTENT", (entity), (sendoffArguments), (sendoffFunction), (id)] – function runs now on the target and then follows the locality of entity (OBJECT | GROUP): whenever the entity becomes local to a machine (ownership change or a joining player), function runs there; on the machine that loses it, sendoffFunction (CODE | STRING) runs with sendoffArguments. Ends with removeHandler or when the entity is deleted.
  • ["PLAYER_PRESENCE", (object), (present), (distance), (jip), (id)] – function runs now on the target, then once more on each player's machine the first time that player's unit is within distance metres of object (present true, default) or farther than it (present false). jip BOOL (default true) also covers players who join later. Ends when every player has been served, object is deleted, or the handler is removed.

Return: ANY - Immediate environment: the function's return (call) or script handle (spawn) when run locally without a special; otherwise usually nil, or [entity, id, true] for "PERSISTENT" and [missionNamespace, id, 2] for "PLAYER_PRESENCE" - Any other environment: handler [[["TEMPORAL"], interval, id, clientOwner], specialReturn]

Variables available inside the function (local, unscheduled runs): _this, _handlerId, _totalDelta, _executionTime (CBA_missionTime at the execute call), _executionCount, _previousReturn, and _argsCallback with "CALLBACK".

removeHandler

Removes a KH handler: an execute handler (temporal execution, including its JIP / persistent / player-presence part), a JIP handle from triggerCbaEvent, or any handler returned by KH_fnc_addEventHandler. Fires KH_eve_handlerRemoved.

Syntax: removeHandler handler - handler: ARRAY – one handler, or an ARRAY of handlers (all removed)

Return: NOTHING

triggerCbaEvent

Fires a CBA event on the machines described by a target, choosing the right CBA_fnc_*Event automatically, optionally as JIP.

Syntax: triggerCbaEvent [event, (arguments), (target), (jip)] - event: STRING name, or [name, entity] (OBJECT | GROUP) for an event scoped to that entity - arguments: ANY – _this in the handlers (default nil) - target: see 1.1 (default true) - jip: BOOL | ARRAY, see 1.2 (default false; a STRING is not accepted here)

Return: ANY – the JIP handle [missionNamespace, jipId, 2] when JIP is used; otherwise the underlying CBA function's return for single-machine dispatch, nil for fan-outs

serializeFunction

Turns a function into a STRING token that can be stored, sent over the network and run anywhere with callSerializedFunction or execute.

Syntax 1: serializeFunction function - function: CODE | STRING (see 1.4). Command names and bare global function names are returned unchanged; code and .sqf paths are compiled and stored under a hash

Syntax 2: isPublic serializeFunction function - isPublic: BOOL – true broadcasts the stored function with a public variable so every machine (including JIP) can resolve it; false keeps it local (a client forwards it to the server)

Return: STRING – the token

callSerializedFunction

Runs a serialized token (or any function form) with arguments. A token not known on this machine is fetched from the server (or from caller) and then run locally and asynchronously.

Syntax: arguments callSerializedFunction [function, (caller), (unscheduled)] - arguments: ANY (nil = no arguments). For a command name: an ARRAY of 0–2 elements - function: CODE | STRING token - caller: SCALAR owner id that should receive the fetched function (default 2) - unscheduled: BOOL – true call (default), false spawn

Return: ANY – the function's return (call) or script handle (spawn); when the token had to be fetched, an execute handler instead (the function's own result is not available)

setReturnValue / getReturnValue / setCallArguments / getCallArguments

Two global one-slot registers the framework uses to pass values between native code and compiled SQF. Overwritten by every framework call; read back immediately in the same unscheduled code.

Syntax: setReturnValue value · getReturnValue · setCallArguments value · getCallArguments - value: ANY

Return: NOTHING for setters; ANY (stored value, nil if none) for getters

3. Lua

The framework runs a Lua (LuaJIT) state alongside SQF. Values convert as follows: SCALAR ↔ number, BOOL ↔ boolean, STRING ↔ string, ARRAY ↔ sequence table, HASHMAP ↔ keyed table; every other SQF type becomes an opaque wrapper that converts back unchanged. Only the first Lua return value is returned; Lua functions cannot be returned (nil). In Lua code, !=, &&, || and ! are accepted as ~=, and, or, not.

luaExecute

Runs Lua code, or a named global Lua function, with arguments and returns the result. With an ARRAY argument the Lua code is dispatched through execute (targets, delays, specials).

Syntax 1: arguments luaExecute code - arguments: ANY – ARRAY elements become separate Lua arguments (...); other values are one argument; nil = none - code: STRING – Lua source (return to produce a value), or the name of a global Lua function (no space or ()

Return: ANY – converted result; nil on error or when nothing is returned

Syntax 2: luaExecute code – as syntax 1 with no arguments.

Syntax 3: arguments luaExecute [code, (target), (environment), (special)] Syntax 4: luaExecute [code, (target), (environment), (special)] - Identical to execute (section 2) with code in place of the function. In a "CALLBACK" special the callback function, and in a "PERSISTENT" special the sendoff function, are also Lua strings.

Return: ANY – as execute

luaCompile

Compiles Lua source and stores it as a global Lua function under a name, callable from luaExecute and Lua.

Syntax: name luaCompile code - name: STRING – global function name - code: STRING – function body; arguments arrive as ...

Return: NOTHING

luaTriggerEvent

Fires a Lua event (handlers registered in Lua with event.add) locally or on other machines.

Syntax 1: arguments luaTriggerEvent event - arguments: ANY – ARRAY elements become separate handler arguments - event: STRING

Return: ANY – the last handler's return value; 0 when no handler exists

Syntax 2: arguments luaTriggerEvent [event, (target), (jip)] - target: see 1.1 (default local) - jip: see 1.2

Return: ANY – as syntax 1 when local; nil when dispatched remotely

Syntax 3 / 4: luaTriggerEvent event · luaTriggerEvent [event, (target), (jip)] – no arguments.

luaSetVariable

Sets a Lua global variable, locally or on other machines.

Syntax: luaSetVariable [name, value, (target), (jip)] - name: STRING - value: ANY – nil clears the variable - target: see 1.1 (default local) - jip: see 1.2

Return: NOTHING

luaGetVariable

Returns a Lua global variable converted to SQF.

Syntax 1: luaGetVariable name - name: STRING

Syntax 2: luaGetVariable [name, (default)] - default: ANY – returned when the variable is nil

Return: ANY

luaEmitVariable

Sends a Lua global variable to other machines, which set the same global there.

Syntax 1: luaEmitVariable name - name: STRING – its current Lua value is sent (to this machine only)

Syntax 2: luaEmitVariable [name, (value), (target), (jip)] - value: ANY – sent instead of the current Lua value when present - target: see 1.1 (default local) - jip: see 1.2

Return: NOTHING (nil)

4. KHData (persistent storage)

KHData files live in Documents\Arma 3\kh_framework\kh_data\<file>.khdata. File and variable names are lower-cased; file names follow Windows rules (no path characters, 1–255 characters). Storable values: SCALAR, BOOL, STRING, ARRAY, HASHMAP (nested), plus CODE, TEXT, NAMESPACE, SIDE, CONFIG, LOCATION, DISPLAY, GROUP (by groupId) and OBJECT / TEAM_MEMBER (by vehicleVarName), all resolved again on read.

writeKhData

Stores a variable in a KHData file, locally or on other machines.

Syntax: file writeKhData [name, value, (target), (jip)] - file: STRING - name: STRING - value: ANY – nil deletes the variable - target: see 1.1 (default local) - jip: see 1.2

Return: NOTHING

readKhData

Reads a variable from a KHData file, or lists its variables.

Syntax 1: readKhData file - file: STRING

Return: ARRAY of STRING – all variable names in the file

Syntax 2: file readKhData name Syntax 3: file readKhData [name, (default)] - name: STRING - default: ANY – returned when the variable does not exist

Return: ANY – the stored value, else default / nil

flushKhData

Writes all pending KHData changes to disk. Also happens automatically at mission start and end.

Syntax: flushKhData

Return: NOTHING

deleteKhDataFile

Deletes a KHData file from memory and disk.

Syntax: deleteKhDataFile file - file: STRING

Return: NOTHING

5. KH Network

A custom TCP transport independent of the engine's network. It must be started with khNetworkInitialize on the server and every client. Event names are case-insensitive. 15.2 See-through (built in)

No command. With antialiasing on (FSAA above 1x), the passes that read the scene's depth – fog, fogScatter, dynamicLightFog, pulse, sunflare, ssgi over the sky, every localized (addLocalPostFX, localSphere) or banded pass, and a user effect that uses it – see through the world's blended surfaces (fences, foliage, glass, smoke and other particles) to the scene behind them, and KH meshes with a "blend" material sort against those layers. While such a pass is on, each frame records the depth and colour behind the layers; the buffers scale with resolution and samples (about 1.2 GB at 3840×2160 with 8x, more once KH meshes sort) and are released after 600 frames with no pass that uses them. The particles' transparency is read per 2×2 pixel block, so very fine particle edges may step. Known limitation: with allowDynamicShadows on, the shadows KH meshes cast onto the world from dynamic lights are not in the recorded colour, so under smoke or glass the distance fog shows them lifted.

34. Creating a melee weapon

34.1 Overview

A melee weapon is a normal CfgWeapons class with kh_* properties. Selecting it copies kh_meleeType into the unit variable KH_var_meleeType, sets KH_var_meleeMode to the first kh_meleeModes[] entry and plays the stance action kh_specialActions. Key binds (CBA, "KH Melee") and the melee AI then call KH_fnc_updateMeleeState with "ATTACK", "BLOCK_IN", "PARRY", "KICK", "TACKLE", ["DODGE", dir]…, which play action names of the unit's current Actions class. The resulting move/gesture state carries kh_melee*Timing[] arrays naming sub-classes of the unit's CfgKHMeleeTypes class, which hold powers, costs, hit box and sounds and the CfgAmmo class spawned on a hit.

A weapon therefore needs:

  1. a CfgWeapons class with kh_* properties (34.2),
  2. a CfgKHMeleeTypes class (34.3),
  3. CfgAmmo classes for each attack type (34.5),
  4. animations: a stance Actions class and move/gesture states with timing arrays (34.4),
  5. optionally CfgSounds classes (34.8). The shipped weapons use the dummy magazine KH_MeleeGeneric.

The shipped KH_SwordGeneric01 (base KH_MeleeWeaponTertiaryBase, melee type KH_MeleeCleavingSharpLightLong, stance KH_MeleeInLightSword) is the worked example:

class KH_SwordGeneric01: KH_MeleeWeaponTertiaryBase {
    scope = 2;
    displayName = "Sword - Generic 01";
    model = "...";                               // launcher-slot model
    handAnim[] = {"OFP2_ManSkeleton", "...\Hum_AbsStaSaf_IdlLhtMel.rtm"};
    kh_specialActions = "KH_MeleeInLightSword";  // ManActions key (+ "KH_MeleeInLightSwordTransition")
    kh_meleeType = "KH_MeleeCleavingSharpLightLong";
    kh_meleeModes[] = {"KH_MeleeAttack01", "KH_MeleeAttack02"};
    kh_meleeModesGestures[] = {{"KH_MeleeAttack01AGesture", "KH_MeleeAttack01BGesture"}, {}};
};

35. KH_Rendering3D (renderer meshes from config)

Attach KH renderer meshes to a class with class KH_Rendering3D. On a CfgVehicles class they are made for every entity of it when it initialises (on every client, and in Eden). class KH_Rendering3D {
    class Blade {
        model = "\x\mymod\addons\main\meshes\blade.fbx"; // addRender3D mesh: "box", "sphere", … or *.fbx
        bindSkeleton = 1;       // default 1: skeletal binding to the entity; 0 = plain attach
        followRotation = 0;     // rotation BOOL of addRender3D (default 0)
        static = 0;             // 1 = created at the entity's position once, not following (ignored in Eden)
        hideInVehicle = 0;      // 1 = hidden while the man is in a vehicle (default 0)
        color[] = {1, 0, 0, 1}; // every other property = updateRender3D [handle, name, value] (not mesh)
        size = 1.5;             // a BOOL property is written 1 / 0 (not rotation: a number there is a yaw)
    };
};

39. Other config

  • Wearable item properties (CfgWeapons uniforms, vests, headgear, goggles/HMDs, CfgGlasses, and CfgVehicles backpacks): kh_postProcessing[] – addPostFX arguments applied to the wearer's screen while worn; kh_teamspeakVoiceEffects[] – a tsApplyVoiceEffects chain applied while worn (multiplayer only, with the "Teamspeak Voice Effect Presets" setting on).
